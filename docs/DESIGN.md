# japan-rail-guide 設計書（ドラフト v0.2）

壁打ちで決めた内容のまとめ＋実現可能性メモ。作成日: 2026-10-07

**v0.2 の方針転換:** 時刻表・乗換・運行情報ではなく、**「見て楽しめる鉄道の基本情報データベース」**を軸にする。時刻表・乗換・運行情報はロードマップ後半に残す（v0.1の案は §7 に保存）。

## 1. ゴール
- 全国の鉄道（事業者・路線・駅・車両形式）を、暇つぶしに眺めて調べて楽しめるデータベースアプリ。
- 利用者はアカウント不要、URLを開くだけ。
- データは月1回程度、自動で更新される。

## 2. 決定事項

| 項目 | 決定 |
|---|---|
| 形態 | PWA（Webアプリ） |
| 対象範囲 | JR・私鉄・地下鉄・路面電車・モノレール等すべて。**新幹線を含む**（路線・駅・車両すべて） |
| 主役のデータ | 事業者／路線／駅／車両形式 |
| 楽しさの核 | 全国地図を眺める／路線・駅・事業者の図鑑／車両・列車の図鑑 |
| 利用シーン | ひとり暇つぶしで眺める・調べる（読み物的） |
| 歴史 | 現存する路線・駅のみ（廃線・時系列表示はしない） |
| 新幹線の定義 | データ上の路線は法令・事業者の区分に従い、「新幹線」タグで横断表示（ミニ新幹線も同様にタグで括る） |
| 路線の粒度 | データ上の路線が基本。愛称・系統名（山手線等）は別項目で紐付け |
| 路線・駅ページの項目 | 開業年・区間・営業キロ・駅数／軌間・電化方式・複線/単線／駅の乗降客数／駅の構造・ホーム数・開業年（※取得可否は §5 で要調査） |
| 入り口・仕掛け | 都道府県・地方からの絞り込み／ランキング・トリビア |
| ランキング | 駅の乗降客数・取り合わせ／路線の長さ・駅数・開業の古さ／極端な駅（最北端・最南端・標高最高・名前が面白い等）／事業者ランキング |
| 車両図鑑 | 主要形式だけ（新幹線・特急・主要通勤型など）。まず質の高いものから |
| 地図 | MapLibre＋自前PMTiles（静的ホスト）。地理的な地図に路線を重ね、ズームで駅・路線が現れる |
| トップ画面 | 全国地図を全面表示＋検索・ランダム・ランキングへの導線 |
| 検索 | 駅名・路線名・事業者名のテキスト検索（ひらがな・ローマ字対応）／地図上の範囲選択で一覧表示／条件絞り込み（開業年・軌間・電化方式・都道府県など） |
| 路線カラー・駅ナンバリング | OSM／Wikidataのタグをベースに、足りない分は手元の補正テーブル（リポジトリ内CSV）で補う |
| 写真 | Wikimedia Commonsの写真をリンク・埋め込みし、ライセンスと撮影者を必ず表示 |
| 解説文 | Wikipediaの要約を出典付きで表示（CC BY-SA）＋データから自動生成する短文 |
| データ方針 | 公開オープンデータのみ（スクレイピングしない）。各データに出典と取得日を表示 |
| 更新 | 月1回程度の自動更新（GitHub Actions） |
| ユーザー機能 | お気に入り駅・路線（端末内保存）／駅・路線・車両ページの共有URL |
| デザイン | 鉄道らしさ全開（路線カラー・駅ナンバリングを前面に）。スマホ優先、ライト/ダーク自動切替 |
| 技術 | TypeScript＋React＋Vite |
| ホスティング | GitHub Pages＋GitHub Actions |
| 言語 | 日本語のみ（多言語化しやすい構造にはしておく） |
| 品質 | データ検証＋主要ロジックの単体テスト＋CI。データ異常時は前回データを維持 |
| 将来拡張 | 時刻表・乗換・運行情報はロードマップ後半。駅・路線IDを共通化して拡張しやすくする |
| リポジトリ | `japan-rail-guide`（Public）。利用者が空のリポジトリを作成 → add_repo して雛形を投入 |

## 3. アーキテクチャ案（たたき台）
```
[GitHub Actions: 月次] 国土数値情報・OSM・Wikidata等を取得 → 検証 → 正規化・名寄せ
                       → 静的JSON／PMTiles生成 → ビルド → GitHub Pages
[フロント: React/Vite PWA] 静的ファイルを読み込み。検索・ランキングはブラウザ内
```
- 駅・路線に永続IDを振り、将来の時刻表／運行情報データを同じIDに紐付けられるようにする。
- 駅詳細・路線詳細は個別JSONに分割し、必要なものだけ読み込む（容量対策）。
- 共有URLは静的ホストなのでハッシュルーティング（`#/station/xxx`）を第一候補にする。

## 4. 画面構成（たたき台）
トップ（全国地図＋検索／ランダム／ランキング）／事業者ページ／路線ページ／駅ページ／車両形式ページ／ランキング一覧／都道府県・地方別一覧／お気に入り／出典・ライセンス表記。

## 5. 実現可能性メモ
確認できたこと（検索結果ベース。一次情報での再確認は未了）:
- 国土数値情報（国土交通省）に鉄道路線・駅のGISデータがあり、無償提供されている。年次の時系列データも含む。
- 公共交通オープンデータセンター（ODPT）は、鉄道・バス等のデータをREST API（JSON）で提供している（後半ロードマップ用）。

**確認できていない／要調査（推測で埋めない）:**
1. 国土数値情報・OSMの正確なライセンス・出典表記条件。
2. 各項目の取得可否：営業キロ・軌間・電化方式・複線/単線・駅の乗降客数（国土数値情報の駅別乗降客数の対象年度・欠損）・駅の構造・ホーム数・開業年・標高・読み仮名・路線カラー・駅ナンバリング。
3. 事業者名・路線名・駅名の名寄せ（データ源ごとに表記・IDが違う）。
4. 新幹線・ミニ新幹線をデータ上でどう識別できるか。
5. 全国PMTilesのサイズ・生成方法と、GitHub Pagesの容量目安（サイト1GB程度）に収まるか。
6. Wikidataの鉄道車両形式データの充実度。図鑑が成立するか。
7. Wikimedia Commonsの画像をアプリから表示する際のライセンス・帯域・埋め込み条件。
8. Wikipedia要約のCC BY-SA表示要件（帰属・継承の条件）がアプリ全体のライセンスに与える影響。

### 5.1 国土数値情報の調査結果（2026-10-07、検索結果ベース）
※公式ページ（nlftp.mlit.go.jp）はこの作業環境のネットワーク設定でブロックされ、直接は読めていない。以下は検索結果に載っていた記述。

**ライセンス（概ね良好）**
- 国土数値情報ダウンロードサイトのコンテンツは、複製・公衆送信・翻案が自由で、商用利用も可能。CC BY 4.0 と互換。
- 加工して利用する場合は出典の明記が必要（例:「〜（国土交通省）を加工して作成」）。
- コンテンツの中には第三者が権利を持つものがある。データセットごとに注記の確認が必要。
- 一次情報: https://nlftp.mlit.go.jp/ksj/other/agreement_01.html

**鉄道データ（N02）** — 製品仕様書 v3.1 あり
- 属性: 鉄道区分(N02_001)／事業者種別(N02_002)／路線名(N02_003)／運営会社(N02_004)。
- 事業者種別は コード1=新幹線、2=JR在来線、3=公営鉄道、4=民営鉄道、5=第三セクター → **新幹線の識別は事業者種別で可能**。ミニ新幹線は在来線扱いになる見込み（要確認）。
- 鉄道区分に モノレール・懸垂式・案内軌条・軌道（路面電車）・鋼索鉄道 を含む → 対象範囲（路面電車・モノレール等）と合う。
- **属性に営業キロ・軌間・電化方式・複線/単線・開業年・路線カラーは含まれない見込み。** 線形状から距離は計算できるが、営業キロそのものではない。

**駅別乗降客数（S12）** — 2024年版が最新、2011年度以降の時系列
- 属性: 駅名・路線名・鉄道区分・事業者種別・重複コード・データ有無コード・備考・乗降客数。
- データ有無コード（2/3/4）で欠損を表す。4=その年度に駅が存在しない。
- 重複コードがあり、同一駅が複数行になりうる → 駅の名寄せが必要。

**§5 要調査項目への影響**
- 営業キロ・軌間・電化方式・複線/単線・開業年・駅構造・ホーム数・路線カラー・駅ナンバリング・読み仮名・標高は、国土数値情報だけでは足りない可能性が高い。OSM／Wikidata／国土地理院標高API等での補完を検討する。
- 要確認: 国土数値情報の他データ（駅の開業年を含む「鉄道時系列」N05系）の使用可否と、現行の収録内容。
